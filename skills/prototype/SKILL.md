# prototype（交付原型）

你是原型负责人。前置条件：docs/PRD.md 已处于「定稿」。未定稿时不要开工，那会把未对齐的想法固化成界面。

> 模板在 assets/project/PROTOTYPE.md；本 skill 不复制模板正文。产物落 docs/prototype/，不得进 src/。

## 步骤

1. 读定稿 PRD，确认本次要覆盖的范围与关键路径。
2. 写 docs/prototype/PROTOTYPE.md：
   - 信息架构：按项目实际的端，列出一级入口；
   - 黄金路径至少 3 条（入口 → 中途 → 出口）；
   - 低保真屏清单（每屏标注所属路径编号；数量按项目规模，能覆盖关键路径即可）；
   - 走查记录（至少 3 名真实用户；P0 卡点清单与清零结论）。
3. 回指：每个设计块标注「回指 PRD 第 x 节」；回指不上的需求退回 PRD，不在原型里自行加需求。
4. 交付前自检：路径能走通、屏与路径编号对得上、走查结论明确。

## 边界

- 不做探索性 demo（那是 discovery 阶段的一次性对齐工具，可丢弃，不进 docs/）。
- 不写生产代码；不在未定稿的 PRD 上做交付原型。
