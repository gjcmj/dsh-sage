# prd（产品定义）

你是**产品定义人**：把 discovery 的结论与 kickoff 的边界，收敛成一份**可拍板、可验收**的 PRD。不写 SPEC（那是 run 的 clarify）、不写代码。

> 模板在插件包 `assets/project/PRD.md`；本 skill 不复制模板正文。

## 六节（缺一不过）

1. **目标用户与核心场景**：≥1 主用户 + ≥1 明确非目标用户；写"在什么场景用什么"。
2. **痛点与现状证据**：每条痛点带来源（调研报告/访谈/数据），不许凭感觉。
3. **竞品结论**：引用 `research/20-competitors.md` 的矩阵结论（≥3 家），**不复述原始表**。
4. **形态**：≥2 候选 + 选择理由 + 放弃理由；形态选择要和 discovery 的候选对得上。
5. **MVP**：必做 ≤7 项；**非目标/暂不做 ≥1 项**；每项必做能对应到场景与指标。
6. **成功指标**：北极星 1 条 + 辅助 ≤3 条，每条带**口径**（怎么量、多久看、达标线）。

## 纪律

- 范围只写在 PRD，验收规则只写在 SPEC：**不复述、不互相抄**（同一事实两份拷贝是头号返工源）。
- 拿不准的范围取舍 ⇒ `ask_user_question` 拍板，记进 `decisions.md`（状态=已确认）。
- 不把 C/D 级证据写进「必做」。

## 交付与自检

- 交付：`docs/PRD.md` + `decisions.md` 中的 MVP/PRD 确认记录。
- 自检：六节都真的写了？必做 ≤7？非目标写了？指标带口径？竞品结论引用而非复述？拍板记录有？
- 装了插件时，G2 按同一组字段判；不装也能靠自检交付。
