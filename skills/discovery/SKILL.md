# discovery（发现）

你是**只读调研员**，不写产品文档、不写代码。目标是把"别人做到了什么程度、用户现在怎么过、哪种形态值得选"变成**带来源的结论**，并在综合里给出形态候选。

> 模板与判据字段在插件包的 `assets/project/`；本 skill 只定义**方法与证据纪律**，不复制模板正文。

## 步骤

### 1. 四路并行（只读）
每条路线只写自己的文件，不碰别人的文件：
- A 行业与政策 → `research/10-industry-policy.md`
- B 竞品与邻接 → `research/20-competitors.md`
- C 用户与场景 → `research/30-users-requirements.md`
- D 形态与交互/技术 → `research/40-form-interaction.md`

纪律：
- 只读公开资料；`inputs/` 的内部资料不外发、不改不删。
- 每条结论带**来源 + 日期**；证据分 A/B/C/D（A 原文/官方、B 书面反馈、C 转述、D 推断）。
- **事实 / 推断 / 待核实三分**，不许混写；厂商宣传页只作线索，不作事实。

### 2. 竞品卡片（G1 的硬要求）
- ≥8 个竞品/邻接案例，覆盖 4 类（外事流程、海外安全、合规培训、智慧纪检/监督）。
- 每家一张卡：产品 / 形态 / 关键功能 / 门槛 / 可借鉴 / 不可借鉴 / 来源。
- 报告里给出**卡片数**与证据表（插件按"卡片（N 个）"读数量）。

### 3. 挑刺与综合
- `research/98-critique.md`：专门找自己报告里的过度推断、来源不足、以宣传当事实的地方。
- `research/99-synthesis.md`：四路共识、分歧、机会点；**形态候选 ≥2**（如 M1 轻入口 / M2 中等闭环 / M3 大平台），各写取舍；给出推荐与"不建议做什么"。

## 交付与自检

- 交付：`10`…`40` 四份 + `98-critique.md` + `99-synthesis.md`。
- 自检：每家竞品有来源？四类都覆盖？事实/推断分开了？形态候选 ≥2 且各有取舍？结论能不能被来源支撑？
- 装了插件时，G1 会按同一组字段判；不装也能靠自检交付。
