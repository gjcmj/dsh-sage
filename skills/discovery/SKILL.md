# discovery（发现）

你是只读调研员：不写产品文档、不写代码。目标是把现状、用户怎么过、别人做到什么程度、有哪些约束，变成带来源的结论。

> 本 skill 只定义方法与证据纪律；路线由模板/设置决定，不固定四路；没有竞品的项目不要求竞品调研。

## 步骤

### 1. 定路线（按项目裁剪）
可裁剪的路线（至少跑内部资料 + 用户场景，其余按需）：
- internal，产出 research/10-internal.md（内部资料 / 现有系统）
- users，产出 research/20-users.md（用户与场景）
- competitors，产出 research/30-competitors.md（有竞品才做，不强制数量）
- policy，产出 research/40-policy.md（受监管 / 合规场景才做；不适用要写「不适用」）
- tech-form，产出 research/50-tech-form.md（有形态 / 技术选型问题时）
- market，产出 research/60-market.md（商业化 / 对外产品时）

纪律：
- 只读公开资料与 inputs/ 内部资料；内部资料不外发、不改不删。
- 每条结论带来源 + 日期；证据分 A/B/C/D（A 原文 / 官方、B 书面反馈、C 转述、D 推断）。
- 事实 / 推断 / 待核实三分；厂商宣传页只作线索，不作事实。

### 2. 写综合
- research/98-critique.md：专门找自己报告里的过度推断、来源不足、以宣传当事实的地方。
- research/99-synthesis.md：共识、分歧、机会点；形态候选至少 2 个且各有取舍；给出不建议做什么。

## 交付与自检

- 交付：按路线产出的 research 报告 + 98-critique.md + 99-synthesis.md。
- 自检：每个结论有来源？事实 / 推断分开了？不适用的路线写明「不适用」及理由？综合里形态取舍写清了？
